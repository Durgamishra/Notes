Topic 1

Introduction & Overview of R

📘 Historical Context & Philosophical Foundations

R is an interpreted, high-level, functional programming language and environment dedicated to statistical computing, data analysis, graphics generation, and quantitative data science. Developed initially by Ross Ihaka and Robert Gentleman at the University of Auckland, New Zealand, in 1993, R was designed as an open-source implementation of the S programming language, which was created by John Chambers and his colleagues at Bell Laboratories in the 1970s. The name "R" reflects both the first-name initials of its original authors and its direct heritage from the S language.

At its core, R is built around a functional and vectorized computing paradigm. Unlike traditional procedural or imperative languages such as C, C++, or Java, where computations are executed through explicit loops and manual pointer/index manipulation, R optimizes multi-element mathematical operations by executing operations over entire vectors natively. This approach minimizes administrative coding overhead and shifts developer focus directly toward mathematical modeling and exploratory data analysis. R is governed under the GNU General Public License (GPL) and maintained actively by the R Development Core Team, ensuring continuous updates, open security audits, and global cross-platform compatibility.

💻 Key Core Characteristics of R

The enduring supremacy of R across data science domains rests upon several architectural characteristics:

  • Vectorized Operations: Mathematical functions operate on vectors naturally without necessitating explicit iterative loops.
  • Comprehensive Package Ecosystem (CRAN): The Comprehensive R Archive Network hosts over 18,000+ packages providing extensions for machine learning, time-series forecasting, and spatial analysis.
  • First-Class Graphics Engine: R features built-in base graphics along with powerful advanced visualization systems like ggplot2 (based on Leland Wilkinson's Grammar of Graphics).
  • Dynamic Typing & Interpreted Execution: Variables are dynamically typed at runtime, eliminating explicit manual compile steps and enabling interactive exploration via the R Console or RStudio REPL.

📌 Quick Exam Revision Notes: Overview of R

  • Origins: Created by Ross Ihaka & Robert Gentleman (1993), based on Bell Labs' S language.
  • Paradigm: Functional, dynamic, interpreted, vectorized statistical programming language.
  • Ecosystem: Managed by R Core Team; package repository known as CRAN (Comprehensive R Archive Network).
  • Primary Strengths: Native vectorized math, superior statistical routines, publication-grade data visualizations.

💻 Basic Syntax Example

R Script - Basic Calculations & Vectorization 
# Basic Arithmetic and Vectorized Operations
x <- c(10, 20, 30, 40, 50)  # Combine function c() creates a numeric vector
y <- c(1, 2, 3, 4, 5)

# Element-wise addition executed natively without loops
sum_vec <- x + y
print(sum_vec)  # Output: [1] 11 22 33 44 55

# Calculating basic statistics
mean_val <- mean(x)
sd_val <- sd(x)
cat("Mean:", mean_val, "| Standard Deviation:", sd_val, "\n")
Topic 2

R Data Types and Data Structures (Objects)

🧩 Atomic Data Types in R

In R, everything is an object. Unlike traditional languages that distinguish between primitive variables and complex objects, even basic scalars in R are vectors of length 1. R supports six fundamental Atomic Vector Types:

  1. Numeric (Double): Default representation for numbers with decimals (e.g., 3.14, 42.0). Occupies 8 bytes of double-precision memory.
  2. Integer: Explicit integer values denoted by appending an L suffix (e.g., 42L, 100L). Stores whole numbers using less memory than doubles.
  3. Character: Text strings enclosed within single or double quotes (e.g., "BCA", 'Data Science').
  4. Logical: Boolean logical constants comprising TRUE, FALSE, or missing value indicator NA.
  5. Complex: Numbers containing imaginary components (e.g., 3 + 2i).
  6. Raw: Raw bytes used for binary data manipulation (e.g., charToRaw("A")).

📊 Fundamental R Data Structures

R builds upon atomic types to construct rich data structures capable of representing complex dimensions and mixed data types:

1. Vectors: One-dimensional sequences of homogeneous elements. Created using the c() (combine) function. If distinct types are mixed inside a vector, R executes Implicit Coercion following a hierarchy that preserves information: Logical → Integer → Numeric → Character.

2. Matrices: Two-dimensional rectangular data structures containing homogeneous data elements organized into rows and columns. Created via matrix(data, nrow, ncol, byrow = FALSE). By default, matrices are filled in column-major order unless byrow = TRUE is explicitly declared.

3. Arrays: Multi-dimensional homogeneous data structures extending matrices across higher dimensions ($N > 2$). Defined using array(data, dim = c(d1, d2, d3)).

4. Factors: Specialized data structures used to store categorical variables representing qualitative data with distinct categories called levels. Created using factor() or ordered() for ordinal data.

5. Lists: One-dimensional heterogeneous containers capable of storing elements of varying data types and structures, including nested lists, vectors, matrices, and data frames. Indexed using single brackets [ ] (returns a sub-list) or double brackets [[ ]] (extracts raw content).

6. Data Frames: The primary 2D tabular structure used in data science. Data frames are heterogeneous, list-like objects where each column represents a variable of uniform type and length, while each row represents a distinct observation.

📌 Quick Exam Revision Notes: Data Structures

  • Coercion Rule: Logical → Integer → Numeric → Character (Least flexible to most flexible).
  • Homogeneous Structures: Vector (1D), Matrix (2D), Array (ND) — elements must be of identical type.
  • Heterogeneous Structures: List (1D), Data Frame (2D) — can store mixed types within distinct components.
  • Matrix Filling: Default is Column-Major. Use byrow = TRUE to change to Row-Major.
R Script - Creation & Manipulation of Objects 
# 1. Vectors & Implicit Coercion
mix_vec <- c(TRUE, 10L, 3.14, "Data") 
print(mix_vec) # Coerced entirely to Character: "TRUE" "10" "3.14" "Data"

# 2. Matrix Creation
mat <- matrix(1:6, nrow = 2, ncol = 3, byrow = TRUE)
print(mat)

# 3. Factor Creation
gender <- factor(c("Male", "Female", "Female", "Male"))
print(levels(gender)) # "Female" "Male"

# 4. List Creation
my_list <- list(ID = 101, Name = "Alice", Scores = c(90, 85, 92))
print(my_list$Scores[2]) # Accessing list contents: 85

# 5. Data Frame Creation
df <- data.frame(
  StudentID = c(1, 2, 3),
  Name = c("Amit", "Priya", "Rahul"),
  GPA = c(3.8, 3.9, 3.5)
)
str(df) # Display structure of data frame
summary(df) # Display summary statistical metrics

Reading and Writing Data in R

📂 Data I/O Pipeline Architecture

Data acquisition and export represent fundamental starting points in the data science lifecycle. R provides robust functions for reading external tabular files (CSVs, text files, delimited text) into memory as data frames, as well as exporting processed objects back to disk or binary serialization representations.

Understanding working directories is essential for file management. The function getwd() retrieves the active working directory, while setwd("path") sets a new working path. For external flat files, base R relies on the read.table() parent function and specialized wrappers like read.csv() and read.delim().

⚙ Key Parameters in Tabular Data Import

  • file: Relative or absolute file path string.
  • header: Logical scalar (TRUE/FALSE) indicating whether the first row contains field names.
  • sep: Character specifying field separator (e.g., "," for CSV, "\t" for TSV, "" for white space).
  • stringsAsFactors: Logical flag indicating whether string variables should automatically convert to factors (Default in R 4.0+ is FALSE).
  • na.strings: Character vector specifying values to interpret as missing values (e.g., c("NA", "N/A", "-999", "")).

📌 Quick Exam Revision Notes: Data I/O

  • Directory Management: getwd() checks active directory; setwd() alters directory.
  • CSV Imports: read.csv() uses comma separator and sets header=TRUE by default.
  • TSV/Text Imports: read.table() uses space separator; read.delim() uses tab separator (\t).
  • Binary R Data: saveRDS(obj, "file.rds") / readRDS("file.rds") for single objects; save() / load() for workspace sessions.
R Script - Complete Data Import/Export Syntax 
# Set Working Directory
# setwd("C:/Users/Student/Documents/R_Work")

# 1. Reading CSV File with explicit parameters
student_data <- read.csv(
  file = "students.csv",
  header = TRUE,
  sep = ",",
  na.strings = c("NA", "", "NULL"),
  stringsAsFactors = FALSE
)

# Inspect imported data
head(student_data, n = 5) # View first 5 rows

# 2. Writing Modified Data back to CSV
write.csv(student_data, file = "students_cleaned.csv", row.names = FALSE)

# 3. Fast Native Binary Serialization (RDS)
saveRDS(student_data, file = "student_data.rds")
restored_data <- readRDS(file = "student_data.rds")

Control Structures in R

🙠 Execution Flow Management

Control structures dictate execution flow within R scripts, enabling conditional decision-making, conditional branching, and repetitive execution loops. Because R is fundamentally vectorized, imperative loops are often replaced by vector operations or apply family utilities; however, traditional control structures remain vital for program logic control.

🔀 Conditional Branching & Iteration Constructs

Decision Making: R provides standard if, if-else, and multi-branch if-else if-else blocks. Additionally, R provides a unique vectorized conditional function called ifelse(test, yes, no), which evaluates an entire vector of conditions at once and returns a vector of corresponding outputs.

Iteration Loops:

  • for Loop: Iterates over a sequence vector or list of fixed length.
  • while Loop: Executes statements continuously as long as a evaluated boolean test condition evaluates to TRUE.
  • repeat Loop: Executes an infinite loop that continues until explicitly terminated using a break statement.
  • Loop Control Controls: break exits loop execution entirely; next skips the current iteration and jumps directly to the next loop iteration.

📌 Quick Exam Revision Notes: Control Structures

  • Vectorized Conditional: ifelse(condition, value_if_true, value_if_false) evaluates vector operations in one line.
  • Loop Types: for (fixed iteration count), while (entry-conditioned), repeat (infinite until break).
  • Control Words: break terminates loop; next skips current cycle iteration.
R Script - Control Structures and Vectorized ifelse 
# 1. Vectorized Conditional ifelse()
marks <- c(45, 88, 32, 95, 67)
results <- ifelse(marks >= 50, "PASS", "FAIL")
print(results) # "FAIL" "PASS" "FAIL" "PASS" "PASS"

# 2. For Loop with Next and Break
cat("Processing numbers:\n")
for(i in 1:10) {
  if(i %% 2 == 0) {
    next # Skip even numbers
  }
  if(i > 7) {
    break # Terminate loop if number exceeds 7
  }
  cat("Odd Value:", i, "\n")
}

# 3. While Loop Example
count <- 1
while(count <= 3) {
  cat("While Count:", count, "\n")
  count <- count + 1
}
Topic 5

Functions in R

🤖 Modular Computing & First-Class Functions

In R, functions are treated as First-Class Objects (or first-class citizens). This means functions can be assigned to variables, passed as arguments into other functions, stored inside lists, and returned from function execution calls. Functions promote code reusability, modularity, readability, and encapsulation.

R includes hundreds of Built-in Functions for mathematical calculations (sqrt(), abs()), statistical aggregations (mean(), sd(), median()), string manipulations (paste(), substr(), sprintf()), and structural inspection (length(), dim(), str()).

✍ Anatomy of User-Defined Functions & Lazy Evaluation

A function is declared using the keyword function with a defined set of arguments, body code enclosed in curly braces, and an optional return() statement. If no explicit return call is given, R automatically returns the evaluated result of the final statement executed within the function body.

Lazy Evaluation: R evaluates function arguments only when they are first accessed during execution, not when the function is initially invoked. This lazy evaluation paradigm saves computational resources when handling heavy data arguments.

📌 Quick Exam Revision Notes: Functions

  • First-Class Status: Functions are objects that can be assigned, passed as inputs, or returned.
  • Implicit Return: R returns the last evaluated expression if return() is omitted.
  • Lazy Evaluation: Argument expression values are computed only when evaluated inside function execution flow.
  • Default Arguments: Function parameters can be assigned fallback default values in declaration.
R Script - User-Defined Functions and Default Values 
# User Defined Function for Calculating Summary Statistics
calculate_stats <- function(vec, scale_factor = 1.0, verbose = TRUE) {
  # Lazy Evaluation: scale_factor is evaluated here
  scaled_vec <- vec * scale_factor
  m_val <- mean(scaled_vec)
  s_val <- sd(scaled_vec)
  
  if(verbose) {
    cat("Mean:", m_val, "| SD:", s_val, "\n")
  }
  
  # Return multiple output metrics as a named list
  return(list(mean = m_val, stdev = s_val, processed_data = scaled_vec))
}

# Invoking Function
data_points <- c(12, 15, 18, 22, 30)
res <- calculate_stats(vec = data_points, scale_factor = 2)
print(res$mean)

Scope Rules in R (Scoping Rules)

🔍 Lexical Scoping vs Dynamic Scoping

Scoping rules determine how R binds free variables within a function call to physical memory values. R employs Lexical Scoping (also known as static scoping), which dictates that free variable values are resolved based on the environment in which the function was defined or created, rather than the environment from which the function is called (dynamic scoping).

🏢 The Environment Hierarchy & Search Path

An Environment in R is a collection of symbol-value pairs, bound together in a hierarchical tree topology where every environment possesses a designated parent environment (except the Empty Environment).

When R attempts to resolve a symbol or variable inside a function body, it follows a strict search path:

  1. Local Environment: Search variables created inside the executing function frame.
  2. Enclosing Environment: Search the environment where the function was declared.
  3. Global Environment (.GlobalEnv): Search user workspace variables.
  4. Package Environments: Search attached external package namespaces listed in search().
  5. Base Environment: Search core system functions and symbols.

Super-Assignment Operator (<<-): Standard assignment (<- or =) binds or updates variables within the current local environment frame. In contrast, the super-assignment operator (<<-) bypasses the local environment and searches upward through parent environments to modify or define global variables directly from within local function execution scopes.

📌 Quick Exam Revision Notes: Scope Rules

  • Lexical Scoping: Symbol lookup relies on function *definition* location environment.
  • Search Path Sequence: Local → Enclosing → Global Environment → Package Namespaces → Base.
  • Super Assignment (<<-): Reassigns or creates variables in enclosing/global environments from within local scopes.
  • Command Check: Execute search() to inspect active package environment lookup orders.
R Script - Lexical Scoping and Super-Assignment 
# Global Scope Variable
x <- 100 

make_power_func <- function(exp) {
  # Lexical scoping: 'exp' is bound in this enclosing environment
  power_func <- function(base) {
    return(base ^ exp) # 'exp' resolved from enclosing environment
  }
  return(power_func)
}

square <- make_power_func(2)
cube <- make_power_func(3)

print(square(4)) # Output: 16
print(cube(4))   # Output: 64

# Demonstrating Super-Assignment Operator <<-
global_counter <- 0

increment_counter <- function() {
  global_counter <<- global_counter + 1 # Modifies global environment variable
}

increment_counter()
print(global_counter) # Output: 1

Dates and Times in R

📅 Time Representation Architecture

Time-series modeling and temporal log data processing require specialized handling in data science routines. Base R handles dates and times using dedicated object classes:

1. Date Class: Used for calendar dates without timestamp components. Internally, R stores Date objects as integer values representing the total number of days elapsed since 1970-01-01 (the UNIX epoch reference point). Dates prior to 1970 are stored as negative integer offsets.

2. POSIXct Class: Stores date-time information internally as continuous signed double-precision floating-point numbers representing seconds elapsed since 1970-01-01 GMT. Highly efficient for storage inside large data frames.

3. POSIXlt Class: Stores date-time values internally as structured, named lists containing individual components such as seconds (sec), minutes (min), hours (hour), day of month (mday), month (mon, 0-indexed), and year (year, years since 1900).

⏰ Key Formatting & Arithmetic Functions

  • Sys.Date() & Sys.time(): Retrieve active system date and time stamps.
  • as.Date(x, format): Converts character strings to calendar Date objects.
  • strptime(x, format): Converts raw character strings into structured POSIXlt objects.
  • strftime(x, format): Formats date-time objects into customized character representations.
  • difftime(time1, time2, units): Calculates precise time intervals across units (seconds, minutes, hours, days, weeks).

📌 Quick Exam Revision Notes: Dates and Times

  • Epoch Reference: Base epoch reference date is 1970-01-01 across R date classes.
  • Date Class: Stores integer count of days since epoch.
  • POSIXct vs POSIXlt: POSIXct stores seconds count; POSIXlt stores list components (sec, min, hour, etc.).
  • Interval Math: Use difftime() for exact time interval measurements between dates.
R Script - Date Parsing, Formats, and Calculations 
# 1. Date Class Operations
date_str <- "2026-10-03"
my_date <- as.Date(date_str)
print(class(my_date))      # "Date"
print(as.numeric(my_date)) # Days elapsed since 1970-01-01

# Custom String Date Parsing
dob <- as.Date("15/08/1947", format = "%d/%m/%Y")
print(dob)

# 2. POSIXct and POSIXlt Operations
now_time <- Sys.time() # POSIXct
time_struct <- as.POSIXlt(now_time) # POSIXlt

cat("Current Hour:", time_struct$hour, "| Month:", time_struct$mon + 1, "\n")

# 3. Date Arithmetic & Time Difference
time_diff <- difftime(Sys.Date(), dob, units = "days")
print(time_diff)

Loop Functions in R (The Apply Family)

🐢 Functional Iteration vs Imperative Loops

In R, traditional imperative loops like for and while can introduce speed bottlenecks when executing complex iterative computations over massive vectors or data frames. R addresses this using the Apply Family of Functions. These built-in high-order functions apply a specified function iteratively across subsets of data matrices, arrays, lists, or data frames using optimized C code under the hood.

🔄 Member Functions of the Apply Family

1. apply(X, MARGIN, FUN, ...): Evaluates a given function across rows or columns of matrices or arrays. The parameter MARGIN = 1 applies computations row-wise, MARGIN = 2 applies computations column-wise, and MARGIN = c(1, 2) operates across both dimensions simultaneously.

2. lapply(X, FUN, ...): Applies a specified function to every element of a vector or list and returns a new List of identical length.

3. sapply(X, FUN, ..., simplify = TRUE): A user-friendly wrapper over lapply that attempts to simplify the output structure. If all elements returned are scalars, sapply converts the final output into an atomic vector; if outputs are vectors of uniform length, it returns a matrix.

4. tapply(X, INDEX, FUN, ...): Applies functions over ragged subsets or subgroups of a vector, grouped by categorical factors defined in the INDEX argument.

📌 Quick Exam Revision Notes: Apply Family

  • apply: Designed for matrices/arrays. Margin 1 = Rows, Margin 2 = Columns.
  • lapply: Returns a List output for vectors or lists.
  • sapply: Simplified version of lapply returning vectors or matrices when possible.
  • tapply: Group-based aggregations using factor category indexes.
R Script - Complete Apply Family Syntax 
# Sample Matrix
mat <- matrix(1:12, nrow = 3, ncol = 4)

# 1. apply(): Calculate column sums (MARGIN = 2)
col_sums <- apply(mat, MARGIN = 2, FUN = sum)
print(col_sums) # Output: 6 15 24 33

# 2. lapply() vs sapply()
str_list <- list(a = 1:5, b = c(10, 20, 30))

l_res <- lapply(str_list, mean) # Returns list
s_res <- sapply(str_list, mean) # Returns simplified named vector

print(l_res)
print(s_res)

# 3. tapply(): Categorical Group Aggregations
salaries <- c(50000, 60000, 80000, 120000, 95000)
dept <- factor(c("HR", "HR", "IT", "IT", "IT"))

avg_salary_by_dept <- tapply(salaries, dept, mean)
print(avg_salary_by_dept)

Debugging Tools in R

🐛 Error Taxonomy & Handling Strategies

Debugging involves diagnosing, isolating, and resolving errors within source code. R classifies runtime occurrences into three primary tiers:

  • Fatal Errors: Unrecoverable failures triggered by syntax flaws or missing symbols that immediately abort function execution.
  • Warnings: Non-fatal alert notifications indicating unexpected conditions; execution continues without terminating.
  • Messages: Informational status outputs that do not impact code execution.

🔍 Built-in Diagnostic Functions

R includes interactive diagnostic tools that allow programmers to step through execution, pause execution environments, and inspect runtime call stacks:

1. traceback(): Prints the call stack immediately after an unhandled error occurs, showing the sequence of function calls that led to the crash.

2. debug(fun) & undebug(fun): Flags a target function for step-by-step interactive debugging. When invoked, R pauses execution upon entering the function, enabling line-by-line inspection. Use undebug() to clear the debug flag.

3. browser(): Suspends function execution dynamically at a specific code line, opening an interactive command prompt directly inside the function's local environment frame.

4. Defensive Exception Handling with tryCatch(): Enables graceful error handling by trapping runtime errors and warnings using dedicated error handlers.

📌 Quick Exam Revision Notes: Debugging

  • traceback(): Inspects call stack history after function crashes.
  • debug(): Activates line-by-line interactive execution mode inside target functions.
  • browser(): Inserts manual programmatic breakpoints directly inside local function code.
  • tryCatch(): Evaluates expressions safely with explicit error/warning recovery handling.
R Script - Interactive Debugging and Defensive tryCatch 
# 1. Defensive Programming using tryCatch()
safe_divide <- function(a, b) {
  result <- tryCatch(
    {
      # Code block to attempt
      if(b == 0) stop("Custom Exception: Division by Zero Attempted!")
      a / b
    },
    error = function(e) {
      cat("Trapped Error:", e$message, "\n")
      return(NA) # Return NA default value on failure
    },
    warning = function(w) {
      cat("Trapped Warning:", w$message, "\n")
      return(NULL)
    }
  )
  return(result)
}

res1 <- safe_divide(10, 2) # Returns 5
res2 <- safe_divide(10, 0) # Traps error safely and returns NA
print(res2)

Simulation in R

🎲 Stochastic Modeling & Probability Distributions

Simulation is the process of using mathematical and computational models to imitate real-world stochastic operations. R is widely used for Monte Carlo simulations, statistical sampling, and probabilistic modeling.

R provides a standardized naming convention for probability distributions, using four distinct prefixes combined with distribution abbreviations (e.g., norm, unif, binom, pois):

  • d Prefix (Density): Computes the Probability Density Function (PDF) or Probability Mass Function (PMF) (e.g., dnorm()).
  • p Prefix (Probability): Computes the Cumulative Distribution Function (CDF) (e.g., pnorm()).
  • q Prefix (Quantile): Computes inverse cumulative distribution quantiles (e.g., qnorm()).
  • r Prefix (Random): Generates pseudo-random variables from the specified distribution (e.g., rnorm()).

🔁 Random Sampling & Reproducibility

The sample(x, size, replace = FALSE) function draws random samples from a vector, either with or without replacement.

Reproducibility via set.seed(seed_value): Because computer-generated random numbers are generated using deterministic Pseudo-Random Number Generation (PRNG) algorithms, setting an explicit random seed using set.seed() guarantees identical, reproducible random output across executions.

📌 Quick Exam Revision Notes: Simulation

  • Distribution Prefixes: d (Density), p (CDF), q (Quantile), r (Random Variate).
  • Distributions: norm (Normal), unif (Uniform), binom (Binomial), pois (Poisson).
  • Sampling: sample() extracts randomized subsets; set replace = TRUE for replacement.
  • Reproducibility: set.seed(integer) ensures identical random number output streams.
R Script - Pseudo-Random Generation and Seed Control 
# 1. Setting Seed for Exact Reproducibility
set.seed(123)

# 2. Generating Normal Distribution Random Variables
# Generate 5 random numbers from Normal Dist (mean = 0, sd = 1)
norm_vals <- rnorm(n = 5, mean = 0, sd = 1)
print(norm_vals)

# 3. Random Sampling with and without Replacement
urn <- c("Red", "Blue", "Green", "Yellow", "White")
sample_without <- sample(urn, size = 3, replace = FALSE)
sample_with    <- sample(urn, size = 10, replace = TRUE)

print(sample_without)
print(sample_with)

Code Profiling in R

⚡ Performance Bottlenecks & Efficiency Analysis

Code Profiling is the process of measuring execution time, memory allocation, and CPU usage across program statements to identify performance bottlenecks and optimize runtime behavior. In data science workloads handling large data frames, inefficient R code can cause processing delays. Profiling helps isolate these performance issues.

🕒 Benchmarking & Profiling Tools

1. system.time(expr): Measures the total time required to execute a given R expression. It outputs three distinct time metrics:

  • User Time: CPU time spent executing the actual R expression code.
  • System Time: CPU time spent executing operating system requests (e.g., disk I/O, memory allocations).
  • Elapsed Time: Total wall-clock time experienced by the user.

2. Rprof() & summaryRprof(): Rprof() starts a built-in sampling profiler that periodically records the active execution call stack (default sampling interval is every 0.02 seconds). Calling Rprof(NULL) stops profiling, and summaryRprof() processes the log files to generate runtime summaries.

Optimization Best Practices: Avoid dynamically growing vectors inside loops (which forces repeated memory reallocations). Instead, pre-allocate full vector or matrix memory upfront, favor vectorized mathematical operations over loops, and utilize optimized apply functions or compiled C/C++ packages like Rcpp.

📌 Quick Exam Revision Notes: Code Profiling

  • system.time(): Returns User Time, System Time, and Wall-Clock Elapsed Time.
  • Rprof(): Sampling profiler that tracks call stack history at specified time intervals.
  • Memory Allocation: Always pre-allocate vector memory; dynamic resizing causes severe slowdowns.
  • Vectorization: Replace imperative loops with vectorized calls to maximize C-level execution speed.
R Script - System Time Benchmarking and Memory Allocation 
# 1. Benchmarking dynamic growth vs Pre-allocation
size <- 100000

# Bad Practice: Dynamic Memory Expansion
time_dynamic <- system.time({
  vec_bad <- numeric()
  for(i in 1:size) {
    vec_bad[i] <- i * 2 # Repeated memory reallocation
  }
})

# Best Practice: Pre-allocated Memory Structure
time_prealloc <- system.time({
  vec_good <- numeric(size) # Memory allocated upfront
  for(i in 1:size) {
    vec_good[i] <- i * 2
  }
})

cat("Dynamic Growth Time:", time_dynamic["elapsed"], "s\n")
cat("Pre-allocated Memory Time:", time_prealloc["elapsed"], "s\n")
